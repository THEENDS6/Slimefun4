# Content Template Style

This project treats content as a compile pipeline:

- Template YAML is for maintainers and may use shorthand, inheritance, grouping, and reuse.
- Compiled YAML is for runtime and must be complete, explicit, and validator-friendly.
- Java runtime should read compiled data and should not infer UI layouts, recipe targets, or missing machine parameters.

## Compiler Directives

Use directives at the largest practical scope.

- `@ot`: Put this on a semantic group or file root to choose the runtime target resource.
- `@io`: Prefer group-level output. Avoid one `@io` per small object when a recipe or machine group can be emitted together.
- `@cf`: Use for real structural reuse. Copying a concrete object is acceptable when the next object differs by only a few fields.
- `@define`: Use only for values referenced more than once, string composition, repeated ids, or large parameterized templates.
- `${...}`: Do not wrap one-off values just to make them look templated.

## Compiled Rules

Compiled output must not contain:

- template directives such as `@cf`, `@define`, `@io`, or `@it`
- unresolved variables such as `${machine-id}`
- runtime layout/style tokens such as `menu-style` or `ui.layout`
- YAML anchors or aliases generated by shared object references
- Java fallback hints such as `tag-fuels`

Every compiled machine UI must contain explicit `ui.slots` entries. Input and output slots must include `state-index` so runtime inventory state has a stable order independent of slot number.

## UI Rules

UI templates may use layout names internally, but compiled UI must list every slot directly.

Each compiled slot should have:

- `role`: for example `decoration`, `input`, `output`, `status`, `button`, `fuel`, `preview`, or `empty`
- `behavior`: for example `locked`, `recipe-input`, `input-filtered`, `output-only`, `status-display`, `button-click`, or `preview-only`
- `state-index` for state-backed input and output slots
- `item`, `item-source`, `action`, and `accepts` where the behavior needs them

Player-visible UI text should use `name-key` and `lore-key` unless the literal is intentionally blank.

## Recipe Rules

Recipes should be grouped by process semantics, not by accidental output file shape.

The compiler groups recipe outputs by template source group and `recipe-type`, so a template source may still maintain many legacy entries while compiled output stays coarse enough to review.

Examples:

- gold refining belongs together as a refining chain
- simple ingot creation belongs in a basic ingot group
- armor crafting belongs in armor groups
- electric processing belongs in electric process groups

Prefer `runtime-machines` when a recipe truly belongs to specific machine ids. Prefer `runtime-machine-tags` when the recipe belongs to every machine that has a capability tag. Multiple tags are treated as an all-tags requirement.

## Machine Tags

Manual machines get default tags:

- `manual`
- the full machine id, such as `sf:compressor`
- the local machine id, such as `compressor`
- the operation name, such as `single-input` or `shaped-3x3`

Manual machine YAML may add extra `tags` when a recipe family needs a stable capability name.

## Output Paths

Do not preserve root section names as duplicated directories.

Expected:

- `content/compiled/content/recipes/custom_example.yml`
- `content/compiled/content/recipes/electric/food-composter.yml`
- `content/compiled/content/recipes/smeltery/smeltery.yml`
- `content/compiled/content/machines/electric-machines/sf_electric_furnace.yml`
- `content/compiled/content/machines/energy-components/sf_small_capacitor.yml`

Not expected:

- `content/compiled/content/recipes/recipes/custom_example.yml`
- `content/compiled/content/machines/electric-machines/machines/sf_electric_furnace.yml`
- `content/compiled/content/machines/energy-components/components/sf_small_capacitor.yml`

## Validation

Run:

```powershell
.\gradlew.bat check
```

This compiles templates and verifies explicit compiled output. Add validation before adding new shorthand so compiled-only runtime remains strict.
